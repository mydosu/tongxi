# 同席 · Agent Hub

个人独立 Windows 桌面多 Agent 协作软件，当前版本 `0.20.0`。已完成本地会话管理、五位成员的真实私聊、绑定项目后的统一项目群聊、当前会话内模型与思考强度切换、无边框窗口与 HUD 浮窗，以及桌面服务更新管理。

代码在 `src/`（TS）与 `src-tauri/`（Rust），构建见「开发与测试」。采用 Tauri 2 + TypeScript + Rust + SQLite，使用系统 WebView2。默认数据库位于 Windows 应用本地数据目录 `local.personal.agenthub/hub.db`，完整路径可在“成员与服务”页查看。旧版数据会事务迁移至当前 schema（v19），保留消息、设置和原生会话映射；迁移前通过 SQLite 保存一份完整旧数据库到同目录 `backups`，包含已提交的 WAL 数据。本机构建产物与冻结的历史版本放在 `release/`，不进版本库。

## 使用

1. 选择 Codex、Hermes、DSH、Claude 或阿尔比恩私聊，点击连接。
2. 会话没单独选模型时用成员的默认模型：Hermes 可由同席另定默认（`set_agent_default_model`，存在本地数据库，不改 Hermes 自己的配置；当前为 `custom:command-code-daily-2:deepseek/deepseek-v4.1-flash`），其他成员沿用各自 harness 的默认。在消息上方直接切换模型与思考强度，选择后自动保存；群聊可先选择成员。下一条消息使用新配置，正在生成的回复保留开始时的参数。右上角“模型设置”也可使用。
3. 输入内容，点击“发送给成员”或按 **Enter**，**Shift+Enter** 换行。中文输入法组合与确认事件不会触发发送。
4. 回复流式显示并保存。思考与正文按出现顺序穿插显示（一段思考、一段正文，像各 CLI 那样），长思考在框内自动换行；正文里的 LaTeX（`$…$`、`$$…$$`、`\(…\)`、`\[…\]`）用本地打包的 KaTeX 渲染。回复进行中可直接插话：Codex、Claude 原生追加引导不打断，其他成员先停止再发送。发送按钮旁的“■ 停止”或在输入框按 **Esc** 停止当前回复，等待原生中断确认。
5. 同一成员可同时在多个私聊、群聊里回复，互不阻塞；只有同一会话里要等上一条回复完成（或插话）。侧栏“成员与服务”的数字是当前已连接的成员数。
6. 私聊和项目专属会话里点“在 CLI 中打开”，把这条原生会话移交给该成员自己的 CLI：同席先从桥/app-server 里卸下这条会话并暂停使用（不再往里发消息），新终端窗口里续上同一条会话（`codex resume`、`claude --resume`、`hermes --resume`、DSH 在本机只有网页版，会打开 `dsh --profile web`，在网页的会话历史里选这条会话，关掉终端窗口即收回）。CLI 窗口关闭后自动收回；也可点“收回到同席”结束 CLI 窗口。收回时把移交期间 CLI 里新增的对话（你说的话、成员的回复与思考，不含工具调用）补进同席聊天记录；同席下次发消息从会话库重新载入，接上 CLI 里的上下文。同席中途重启也不丢移交状态：CLI 窗口还开着就继续等它关闭，已经关了就立刻收回。回复进行中不能移交；阿尔比恩在 WSL 里，暂不支持。
7. 软件重启后重新连接，继续发送即可恢复该私聊的原生上下文。

Codex、Hermes、DSH、Claude 在普通私聊和项目成员页需要你补充信息时，会在问题下显示“回答”按钮，并在侧栏显示待答提示。点击“回答”打开选项下拉框与文本输入，可以选一个选项，也可以自行输入或补充；提交后继续同一原生会话。关闭回答窗口不会替你选择。私聊问题与回答只保存在本私聊，不自动广播到团队。已结束回合的待答问题重启后保留；仍在原生回合中等待的问题会随中断取消，不自动重放。阿尔比恩本轮不接入此问答机制。

输入框支持粘贴图片和文件，也可点击“＋”选择附件；Windows 资源管理器中复制的文件通过原生剪贴板接收。附件保存在同席数据目录的会话附件目录，草稿保留附件，提交失败时不清空；提交成功的附件会保存在本地消息中。删除草稿中的附件不会发送该文件。消息显示文件卡片和图片缩略图，点击可下载。每个附件最大32 MiB，每条消息最多20个。Codex 私聊把真实图片文件作为原生 localImage 输入；其他成员通过原生文件/图片/视觉工具按需读取本地附件，具体看图能力取决于当前模型和工具。群聊及项目请求保留附件路径供成员读取，不把完整文件内容塞进群聊正文。

工具输出在普通模式和 HUD 中默认只显示本轮最近工具的摘要。点击展开本轮完整工具历史，再点某一项查看输入输出；流式更新保留用户的展开状态。HUD 工具区保持透明，用字号、颜色和细线区别正文，展开的工具历史限制高度；HUD 正文与输入栏使用同一内容宽度。

未绑定项目的群聊可选择二至五位成员和 1—3 轮讨论；成员按顺序共享本群公开发言。绑定项目后，讨论与开发共用同一个群聊和输入框：直接发送问题、想法或项目目标，Agent 会先理解本轮意图；需要改文件时自动规划、分工、实现和验收，普通讨论则直接回复，不制造空任务。当前消息定义本轮目标，之前的群聊记录只作背景；私聊和其他项目不会混入。阿尔比恩在群里可以陪伴交流，不承担项目编码任务。

“停止讨论”取消当前原生回复并阻止后续成员和轮次。等待停止确认；超时则断开对应的同席子进程。失败后保存已经公开的回复，后续发言不继续启动。重启保留讨论和独立原生会话，未完成讨论标为中断，不自动重放；可以发送新需求继续。

窗口没有系统标题栏。拖动左上角品牌区域或会话头部空白处移动窗口，双击这些区域最大化/还原；右上角保留最小化、最大化/还原、关闭按钮，窗口边缘保留原生缩放。

## 项目协作

在群聊中点击“绑定项目”，选择一个项目目录。这个群聊一次绑定一个项目；绑定后，点击侧边栏的项目主按钮即可展开或收起“团队对话”“项目协作进度”和各 Agent 专属页。先在“项目成员配置”选择需求管家并设置提供商、模型与思考强度，在团队页按 Enter 发送目标即可启动；可在消息中指定“由 Hermes 规划、DSH 实现、Codex 验收”等角色，未指定时由 Agent 安排。普通问题会在群时间线内得到答复；涉及代码时自动分工、实现并验收。

方案、实现和验证等成员任务使用独立 Git 工作树；互不依赖的任务可并行，有依赖的任务等待前置结果。同一成员的工作排队执行。任务输出完成后先提交改动、按顺序合并，再标记任务完成；收尾任务在其他工作合并后的项目目录执行。成员使用各自 CLI 已配置的原生工具、MCP 与插件。合并冲突保留现场与已有输出，不会丢弃改动；未完成结果继续交给管家协调，框架不强制只修复一次。团队页只展示公开头像气泡、真实问题和最终结果；流程状态与工作安排在独立“项目协作进度”页显示；思考、工具及完整输出留在成员专属页。阿尔比恩可以陪伴交流，不承担技术阶段。

在“项目成员配置”中独立选择调度管家和默认方案者。管家从现有 Codex、Hermes、DSH、Claude 中选择，用独立进程、数据目录和原生会话处理路由；它不出技术方案，不操作项目，也不向成员添加自由业务指示。路由仅记录用户原文引用、成员、任务用途、模型授权来源、依赖与已有结果引用，后端据此构造成员请求。你可要求同一成员出方案并承担部分修改，其他成员负责剩余实现、验证、文档或收尾；明确的成员和模型优先，未指定模型沿用项目成员配置。管家每轮接收成员结果再决定后续安排，不向全部成员同时广播完整任务等待抢领。管家会话不会新增侧栏或私聊页。

验证任务最后写明“验证结论：通过/未通过”，未通过时列出问题清单。管家据此把原实现原文再派给原实现成员返修（附验证结果），返修完成后再派验证成员复核；同一项工作最多返修两轮，仍未通过就向用户提问；用户每回答一次（如同意继续），再放行两轮。验证成员已有两次未通过或异常，或用户一开始就要求“用执行者的子代理验证”时，管家可改派子代理验证：任务交给最近完成实现的成员，由它用自带的子代理工具（Claude 为 Agent 工具）派低价模型（haiku/flash/mini 等，优先当前提供商）、high 思考强度的子代理独立验证，它只转述子代理结论、不自己代验；管家不直接派子代理。任务标题为“子代理验证”。成员因模型额度用完或限流而失败时（“限流”“额度”“rate limit”“429”等），管家不判失败也不中断，而是从报错里读出额度重置时间（如 Codex/Claude 的五小时窗口），在团队里说明后等到重置后一分钟自动重试该任务；读不到重置时间才按 5、10、15……最长 30 分钟的间隔重试（管家自身被限流也一样），等待时间不计入协作时长，期间可随时停止。是否返修、由谁返修由管家决定；成员之间仍可用 hub_message 直接补充细节。

派发新任务前若项目仓库有未提交改动，管家先把它们单独提交（作者 agent-hub），在团队时间线说明后继续任务，不再中止协作；凭据文件、生成与依赖目录、链接不提交，只加入本地 `.git/info/exclude`。仓库正处于合并冲突或变基中途时不自动提交：管家在团队时间线汇报冲突文件，由担任管家的成员用自己的项目会话在项目目录完成这次合并或变基（保留双方改动，不得丢弃），框架核实仓库已恢复正常后继续任务；任务分支合并回项目时出现冲突也走同一流程，核实分支确实已并入。处理后仍未解决才停下并保留现场。

绑定普通目录时，同席会自动初始化本地 Git 仓库并提交安全基线，不会推送。基线只纳入安全扫描通过且未被项目忽略规则排除的文件；环境变量、凭据、密钥、生成目录、链接和嵌套仓库不会被加入。

团队页和暂停页不再提供阶段设置入口。角色直接在群聊中指定，提供商、模型和思考强度在“项目成员配置”统一保存。每个成员的项目执行与项目内私聊共用同一个原生 CLI 会话，上下文互通；成员之间各自拥有自己的会话；可通过 hub_message 直发给项目成员、hub_inbox 读取收件箱、hub_broadcast 发布团队消息。私有直发只在相关成员模块可见，公开广播在团队时间线中显示一次；私聊回复也可手动分享到团队。

进度页显示成员状态、已完成任务数和工作安排。“暂停协作”停止整个协作；成员专属页可以只停止该成员，其他独立任务继续，依赖任务等待，并通知团队。失败或中断后点击“继续协作”，或发送“继续协作”消息即可复用原方案、完成任务和保留的工作树；恢复时可在消息中重新指定未完成任务的执行者。软件重启保留记录并把未完成协作标为中断，不自动重放。新协作中，用户暂停后发送纠正内容会继续原工作流。管家先协调新的方向和后续分工，可引用用户纠正原文取消尚未完成的旧任务；已完成改动保留，需要回改时应交给成员明确说明。取消的前置任务不会冒充依赖完成，后续工作需要重新协调。Agent 通过 hub_ask_user 提问，问题作为公开气泡显示；可以直接在群聊回答或点击问题旁的回答按钮。等待回答不消耗协作执行时间预算，收到实际回答后继续同一原生会话。退出或取消会终止旧问题等待。

当前最多两项项目协作。同目录或父子目录项目共享写入排斥，冲突任务等待；同一成员不能同时执行项目步骤和聊天回复。项目尚未结束时，技术成员不能被断开。新协作的附加文件工具开放项目目录，受保护路径与链接越界仍拒绝；旧工作流恢复保持原文件范围。CLI 自带工具由各 Agent 的原生 CLI 配置决定。验收由 Agent 对照本轮目标、方案和实际源码完成，不运行固定检查脚本。修改前保存原文件和元数据，这些记录不等于自动回滚或操作系统级沙箱。阶段验收使用框架自建的隔离项目，没有自行修改用户已有项目。

消息和进度页的本轮工作安排支持右键删除。删除协作会同时清除同席数据库中的本轮请求、方案、任务、尝试、工具事件和成员消息，不保留空方案；项目文件与 Git 提交保留。运行中的消息或协作须先停止。删除协作还会清理该轮独立管家会话缓存；其他原生客户端的成员历史与项目长期记忆保留。

验收只接收目标、文件路径、变更信息和任务结果摘要，由原生 Agent 使用工具按需搜索、分段读取并验证源码；没有框架规定的整体源码快照上限。上下文先由原生 harness 管理压缩。若原生处理后仍明确报告超限，框架保留实现结果并自动按原任务分段验收，将恢复原因传入 Agent 请求及规划成员收件箱，无需用户重新拆分任务。

## 项目记忆

项目记忆分两层，保存在 OpenViking 的 `viking://resources/tongxi/projects/<project-id>/` 下：

- **共享项目记忆** `shared/`：本项目所有技术成员（Codex、Hermes、DSH、Claude）都能检索和读取，也都能新增；每条共享笔记只有作者本人能修改，同名冲突会被拒绝。
- **成员私有记忆** `private/<agent-id>/`：只有该成员自己能读写、列出和检索。旧版按成员分目录（`<project-id>/<agent-id>/`）的笔记归入该成员的私有区。

工具：`hub_memory_write` 默认写入私有笔记，`scope=shared` 直接写入共享区；`hub_memory_share` 由成员自主挑选一条私有笔记分享到共享区，私有原件保留，共享副本记录作者与来源；`hub_memory_search` / `hub_memory_list` / `hub_memory_read` 只返回共享区和调用者自己的私有笔记。跨项目 URI 一律拒绝；疑似凭据的内容拒绝保存。不把私聊原文、完整思考或凭据写入项目笔记。阿尔比恩不接入项目执行工具，开发摘要仍按项目开关发送。

私有是同席工具层的约束：数据仍在 OpenViking 的 resources 中，持有自己 OpenViking 凭据的客户端可以绕过同席直接访问。需要存储层面的隔离时，应让各成员以自己的身份写入各自的私有池。

使用已安装的 OpenViking SDK 和本机服务，默认检测 `D:/AI/openviking/venv/Scripts/python.exe`，可通过 `AGENT_HUB_OPENVIKING_PYTHON` 指定。同席没有 harness 身份，使用中立 `tooling` 身份的专属配置：默认 `~/.openviking/ovcli.tooling.conf`，可用 `AGENT_HUB_OPENVIKING_CONFIG` 指定；共享的 `ovcli.conf` 顶层 key 应保持为空，以免各 agent 被解析成同一身份。记忆子进程不继承启动环境里的 `OPENVIKING_*` 变量，避免借用某个 agent 的身份。服务不可用、认证失败或参数不合规时工具返回明确原因（不含凭据），项目继续执行；写入后语义索引在后台刷新，直接读取立即可用。

## 模型与思考强度

设置按 **会话 × 成员** 存入 SQLite。群聊中的成员分别保存，已有私聊设置保持独立；修改和恢复默认不会删除聊天历史，也不修改 agent 的全局配置。回复期间可以修改下一轮设置，当前轮参数在开始时冻结；已归档会话不能修改。保存期间暂停发送，避免新消息使用尚未保存的参数。

项目协作沿用集中项目成员配置保存的模型与思考强度；显式指定执行者时，该成员承担本轮实现任务，未指定时可自动分派。已启动请求的参数固定，项目成员配置的修改影响下一次请求和恢复时的未完成任务。选择提供商会同步保存该提供商下的明确模型，避免仍沿用旧线路默认值。Hermes 的实际模型记录保留提供商身份，Daily One 与 Daily Two 不会仅以相同基础模型名混淆。项目文件工具保留工作流记录，hub_message/hub_inbox 支持工作流和成员独立私聊的跨 Agent 通信。

连接 Codex 后，模型和强度选项来自 `model/list`。模型留空时沿用连接时读取的本机有效默认模型/强度；显式选择模型、强度留空时采用该模型目录给出的默认强度。发送时再次校验能力，将模型与 effort 传给 `turn/start`。切换模型继续使用原 thread，恢复默认会明确覆盖之前的 turn 设置。

连接 Hermes 后，模型来自本机原生模型目录，包括提供商路由。薄适配层把思考强度赋给当前 agent 的 `reasoning_config`；“默认”恢复该模型按 Hermes 配置得到的初始设置。Hermes 会按模型和提供商映射思考等级，可能下调或忽略不支持的等级，因此不保证每个等级原样出现在提供商请求中。

DSH 复用本机 Hermes 里配置的两条路由（代码按 provider id `command-code-daily` 与 `command-code-daily-2` 匹配）。切换选项代表切换 API 线路；默认使用第一条线路及 low 强度。支持 off / low / high / max 选项，通过原生 ACP `session/set_config_option` 应用到同一个 native session。目录中的能力声明不代表各等级已逐一验证提供商实际执行，真实验收覆盖 off、low 和 high。

连接 Claude 后，模型和各模型支持的思考强度来自本机 Claude Code 的账户模型目录（stream-json 控制协议 initialize，不发送模型请求）。模型留空沿用 Claude Code 自己的默认模型；强度留空不传 `--effort`，由 CLI 按模型决定。每次发送以同一原生会话 `--resume` 续接，切换模型或强度只影响下一轮。

阿尔比恩使用 WSL 内原有 albion profile 的模型和认证。连接后读取原生目录，模型／强度设置只影响本会话下一次发言。软件加载她原有的 SOUL 人格文件，不修改源人格文件。受邀群聊使用独立原生 session，不导入任何私聊。

目录可见不等于账户有调用权限，以真实请求成功为准。断开连接后可以保存待验证的设置，发送时再次校验；失效的设置会产生明确失败状态。

## 已实现的边界

- 五个成员：Windows Hermes、Codex、Windows DSH、Windows Claude、WSL 阿尔比恩。群聊可绑定单一项目；绑定后一个输入框承载讨论和项目目标，协作自动规划、分工、实现与验收，结果留在同一时间线。每个实现任务使用独立 git 工作树，依赖排序、冲突保留现场。阿尔比恩为陪伴与开发知情，不承担项目编码。
- 私聊、二至五位成员群聊、改名、搜索、归档、恢复、确认删除、成员管理。草稿和上次选择在重启后恢复。
- 未绑定项目的群聊保留多成员／多轮讨论；绑定项目后每条用户消息进入统一协作流程。新协作由管家按原文分派方案、实现、验证、收尾或普通回复任务；信息不足时先提问并等待回答。旧协作继续保留原方案和恢复路径。
- 群提示仅包含该群已提交用户消息和公开回复，排除未发送草稿、其他群和全部私聊。调度器构造的公开记录上限为 64,000 字符；历史单条最多 12,000 字符，超长会明确标记截断，当前需求完整保留。原生 harness 自身的会话历史另由其管理。
- Codex 私聊与项目角色启用完整文件、命令、MCP、插件及网络访问权限，且不等待逐项审批。原生 `thread/start`/`thread/resume`、流式事件、`turn/interrupt`；运行信息与会话参数保存到本机。项目 Agent 另有 hub_* 工作流工具。
- Hermes 私聊与项目模式均保留本机 Hermes CLI 的工具、MCP 与插件；项目会话额外接入 hub_* 工作流工具。独立原生 SessionDB 位于同席数据目录 `hermes-native/sessions.db`。
- DSH 真实 ACP 私聊，复用安装的 harness，并开放原生 PowerShell、文件读写与搜索、后台任务、子 Agent、技能、Web 工具及模型路由配置。权限由 DSH harness 在同席中启用完整模式。独立原生会话位于同席数据目录 `dsh-native/sessions`，支持原生续聊、中断和重启恢复。
- Claude 复用本机安装的 Claude Code CLI：嵌入 EXE 的薄适配脚本 `claude_bridge.mjs` 以 ACP 对接，每轮启动一次 `claude -p` 的 stream-json 进程并续接同一原生会话；文件、命令、MCP、插件与技能按用户自己的 Claude Code 配置提供，权限为完整模式（`bypassPermissions`）。原生会话保存在用户自己的 `~/.claude/projects`，Claude Code 命令行也能打开；同席只记录会话 ID 与工作目录。停止使用原生 interrupt 控制请求，8 秒未退出再结束进程树。CLI 自带的 AskUserQuestion 在同席中关闭，提问统一走 hub_ask_user。作为管家时不提供任何内置工具与 MCP、不加载用户设置，管家指令整体替换默认系统提示。认证沿用 Claude Code 已登录的账户，同席不读取也不刷新令牌。
- 阿尔比恩真实私聊走 WSL 内由她自己的服务进程提供的本机 OpenAI 兼容端点（默认 `127.0.0.1:8650`）；人格、记忆与工具都在该服务里，同席只当客户端。软件不启动也不停止该服务，新建私聊分别保存自己的原生会话，不导入原有私人聊天。
- 阿尔比恩回复中原语音系统的结构化情绪控制标记不会进入聊天正文；流式分片期间也会隐藏未完成标记。用户输入保持原文。
- 五位成员的项目执行与私聊各自最多一个同时运行的 turn，可分别连接或断开；消息和状态按成员隔离。隐藏管家使用独立客户端，不占用同一成员的项目会话。运行中的会话禁止归档、删除或更改成员。
- 更新管理：DSH 与 Codex 可检查 npm 发行版、准备隔离候选、原生预检后启用并回退；Hermes 由其自身更新通道处理，同席只读检查；Claude 核对 npm 发行版，安装依赖 postinstall，更新交给 `claude update`；阿尔比恩因 WSL 安装含本地定制，仅检查本地版本，不自动覆盖。
- 退出软件清理软件创建的原生进程树。重启时把未完成运行标为中断，不自动重放请求。
- 原生接口通过 stdio JSON RPC 通信，Tauri 事件传递增量，SQLite 保存结果。递增 revision 避免旧状态覆盖新状态。

Hermes、DSH 与 Claude 薄适配脚本嵌入 EXE，复用本机安装的 Python / Node / 原生 harness，不修改安装源码。Codex 和 Hermes 使用已有认证；DSH 的两条路由认证由 Hermes 原生解析器只读解析，通过私有子进程管道及临时进程环境传递，不输出到界面、日志或验收报告，不保存到同席配置或凭据文件。认证在连接时解析，修改外部凭据后需要重新连接。软件不改变全局模型设置，也不导入旧桌面会话；没有改动现有 agent 的技能、服务和自启。

阿尔比恩的原生数据库放在 WSL 的 `/root/.local/share/local-agent-hub/instances/<namespace>/albion-native/sessions.db`。Windows 数据目录的 `albion-wsl.json` 保存无凭据的 namespace、发行版和 profile 绑定；软件不依赖 Windows 盘符自动挂载。完整备份需要同时保存 Windows 数据目录和对应 WSL instance。更换发行版或 profile 时使用独立数据目录，避免混用原生会话。源 profile／安装源码在该私有子进程中设置写入保护，原生人格加载时明确绑定 profile，避免独立 SessionDB 导致人格目录误判。

Codex 参数依据 [OpenAI App Server 官方文档](https://developers.openai.com/codex/app-server)，并以本机生成的协议 schema 核对；验收还只读核对了本次新建测试 thread 的原生 turn-context 模型/effort 字段。Hermes 接口与映射依据本机安装源码。DSH 接入依据 [DSH 官方 ACP 文档](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/acp/acp/README.md)及本机安装源码。

构建需要 Rust/MSVC、Node 和 WebView2，见 [Tauri 前置条件](https://v2.tauri.app/start/prerequisites/)。构建后自动复制程序至 `release/Agent Hub.exe`，生成大小和 SHA256 清单 `release/manifest.json`。依赖锁定于 package-lock.json、Cargo.lock。

Codex 从 PATH 中查找原生 exe，也支持 `AGENT_HUB_CODEX_EXE` 指定绝对路径。Hermes 默认发现 `%LOCALAPPDATA%/hermes/hermes-agent/.venv/Scripts/python.exe`，也支持 `AGENT_HUB_HERMES_PYTHON`；该 Python 必须属于带有原生 ACP 模块的 Hermes 安装。DSH 与 Codex 的安装目录默认从 PATH 上的 `dsh` / `codex` 反推（CLI 壳同级的 `node_modules/<scope>/<包名>`；npm -g 全局前缀与自带 `node_modules` 的独立安装都适用），也可用 `AGENT_HUB_DSH_INSTALLATION` / `AGENT_HUB_CODEX_INSTALLATION` 直接指定。Node 从 PATH 查找，可用 `AGENT_HUB_DSH_NODE` 指定。两条 Hermes 路由必须存在，可用 `AGENT_HUB_DSH_HERMES_REPO` 指定 Hermes 仓库。软件自身不安装或更新这些 harness。

Claude 默认使用 PATH 上的 `claude.exe`，或 npm 壳 `claude.cmd` 同级的 `node_modules/@anthropic-ai/claude-code/bin/claude.exe`，再回退到官方安装器的 `~/.local/bin/claude.exe`；可用 `AGENT_HUB_CLAUDE_EXE` 指定。适配脚本所需的 Node 可用 `AGENT_HUB_CLAUDE_NODE` 指定，否则与 DSH 一样从 PATH 查找。

阿尔比恩默认连接本机 `127.0.0.1:8650` 的 OpenAI 兼容端点，可用 `AGENT_HUB_ALBION_ENDPOINT` 指定；该服务读取的 `.env` 可用 `AGENT_HUB_ALBION_ENV` 指定。服务由她自己的进程启停，同席只做客户端。
